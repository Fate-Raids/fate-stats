# PlusOne Raid Archive — GitHub Edition v0.3.0 Handoff

## Current architecture

Static site served by GitHub Pages (`index.html`, `assets/`, `data/archive.json`), using unchanged established PlusOne UI. The GitHub repository itself is the administrative upload mechanism; there is intentionally no PHP, server, login, database, API tokens, or public upload button. Authorized writers commit raw exports in `raid-exports/`. GitHub Actions runs tests, executes `scripts/build-archive.mjs`, uploads `dist/` as a Pages artifact, and deploys it. The current browser parser accepts the `plusone-web-archive-v1` published format and retains the full raw payload for future analysis.

## Important contracts

- Keep the previous FATE charcoal/cyan design and v0.1.2 badge-height fix; avoid `.main` class collisions with Main Spec badges.
- Parser source: `assets/parser.js`; browser IIFE bundle: `assets/parser-browser.js` generated by `node scripts/build-browser-parser.mjs`.
- No live site integration with PHP. No secrets, access tokens, or account credentials client-side.
- Do not preload samples into production without user intent.
- Preserve source JSON intact and maintain support for `PlusOneRaidHistory-4` and `plusone-web-archive-v1`.
- Test with synthetic session: 20 raiders, 60 loot awards, 26 SoftRes slots.
- Publishing job should fail loudly on malformed JSON rather than silently omitting files.
- Original JSON and Git history are publicly accessible in a public repository; do not recommend uploading confidential fields.

## Future enhancements

Session-overlap detection/merging across different full-history exports, robust source schema adapters grounded in real PlusOne exports, class/role history, long-term +1 scores, improved Wowhead data caching, optional guild-themed header, item detail modals, group-wide filters, enhanced sharing, and serverless-authenticated admin UX if ever needed. Distinguish imported loot outcomes from SoftRes reservations. Any schema migration is unnecessary during alpha.
