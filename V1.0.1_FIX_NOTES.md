# FATE Guild Armory v1.0.1 — GitHub Actions Test Compatibility Fix

## What failed
The original v1.0 GitHub upload ZIP omitted the updated test suite. After upload to the existing v0.5.2 repository, the retained `tests/publisher.test.js` still attempted to read the removed file `dist/data/archive.json`, which produced 6 ENOENT failures. The v1.0 generated manifest is `dist/data/manifest.json`, and characters/sessions/items live in separate files.

## Fix
- Upload the v1.0.1 **GitHub Upload** package into the existing GitHub repository root and allow **overwriting existing files**. Crucially, replace `tests/publisher.test.js` (not just add the other test files). The upload includes all tests, reference fixtures, samples, and deployment workflow.
- Alternatively upload the **Minimal Patch** ZIP, which replaces the publisher test and workflow and adds the catalog test and its required fixtures. Either path corrects the six failures.
- The workflow now uses modern GitHub action runtimes and pins the runner image to `ubuntu-24.04` to avoid unrelated Node 20 / forthcoming `ubuntu-latest` notices.
- No raid session JSON files are modified, deleted, or included in the patch. Preserve everything already in `raid-exports/`.

## Why not bring back archive.json?
`archive.json` was intentionally removed to avoid downloading an entire multi-year archive for each visit. The new individual character, session, and item records are the supported v1 structure. Tests were upgraded to check that structure.

## Verification
1. Verify `tests/publisher.test.js` no longer tries to open `dist/data/archive.json` (it now opens `manifest.json`).
2. Commit the replacement files to `main` and open GitHub **Actions > Publish PlusOne Raid Archive**.
3. The test step should show **39 passing automated tests** (on the v1.0.1 codebase); the archive build should then generate `dist/`, and the deployment should proceed.
4. If it still fails, expand the failed job and share the first red error message, not just the annotations summary.

Files uploaded to `raid-exports/` are inputs and remain intact. This release changes the test/upload packaging and workflow but does not change the importer, character projection, UI, or existing archived data.
